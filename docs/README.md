## About `vault/`

`vault/00 Index.md` is its entry point, and the reading order it gives is the right one: context, spec, plans, reference,
logs. Two things to know:

- **The vault is the source of truth, this is a copy.** Re-copy it rather than editing here.
- **`[[wiki links]]` do not resolve on GitHub.** They are Obsidian links between the vault notes; the file names they
  point at are all present in `vault/`.

The daily log is where every number in the write-up was recorded first — including the ones that turned out to be wrong
and why. The decision log gives each decision the alternative it beat, and keeps the superseded and rejected ones.

## Where the numbers live

Nothing in the write-up is typed in by hand. Each figure comes from a generated file:

| number | generated by | file |
|---|---|---|
| correctness counters, priority classification, spreads, OFI, queue results | `research/report.py` | `research/results/numbers_<day>.md` |
| the three-day comparison | `research/crossday.py` | `research/results/crossday.md` |
| throughput, latency percentiles, allocation per message | `ops/bench.sh` → `ops/perf_table.py` | `docs/perf.md` |
| the counters and logs behind each replay | `Replay` | `research/results/runs/<day>/` |

`research/results/runs/<day>/` is the small, permanent residue of each full-day run — `validation.json`, the replay and
probe logs, the probe symbol list, the MeatPy export and the demo ladder slice. It is what lets the write-up stay
reproducible after the bulk data (tens of GB of NDJSON per day) has been deleted.
