## 2026-09-20 (late) — the demo was not laggy, the clock was frozen
**Did:** Chased a report that 1× playback "looks very laggy". It is not a rendering problem. Measured the slice: 606 snapshots over **431 s**, so at 1× the replay runs **7.2 minutes**; snapshot gaps are p50 0.146 s but p99 **10.9 s**, and the longest is **55.8 s** starting 09:28:34.400. Before the open there are only **52 snapshots across 282 s** — one update every 5.4 s. Snapshots exist only where the top of book changed, so the stillness is real and correct. **The defect was that the clock was painted only inside `render()`, which runs only when the snapshot index changes** — so through a 55.8 s stall the clock froze too, and a quiet market was indistinguishable from a hung page.
**Fixed:** `paintClock(simT)` now runs every animation frame while playing, so time moves even when the book does not; a readout says "book unchanged for N s" once a stall passes two seconds, which turns the stillness into information instead of a fault; and the default speed is **10×** (43 s for the whole replay) with 1× still available. Verified deterministically by driving the real page script under a DOM shim with a controlled rAF clock: starting at the stall, the clock advances monotonically, the readout reads "book unchanged for 50 s", and the ladder markup is byte-identical across the stall (4,667 bytes at both samples).
**Also:** registered the Playwright MCP server at user scope. Chromium from the Playwright cache could not start — `libnspr4`/`libnss3` missing, no root — so the `.deb`s were fetched with `apt-get download`, extracted with `dpkg-deb -x` into `~/.local/lib/chromium-deps`, and the server carries `LD_LIBRARY_PATH` pointing there. Both the full chromium and `chrome-headless-shell` now resolve every library. It reports connected, but MCP tools load at session start, so it is available from the next session on.
